# Personal writing style

Write something the user can send with minimal editing: clear purpose, practical
detail, measured claims and a natural professional voice. Preserve the user's
intent without copying typing mistakes or making the language unnecessarily formal.

## Read the right reference

1. Read [the writing guide](references/writing-guide.md).
2. Read the closest example for a substantial draft:

   | Task | Reference |

   | Security, digital forensics or investigation blog post | [Technical blog post](references/examples/technical-blog-post.md) |

All examples are newly written and fictional. Use their tone and level of detail,
not their facts, commitments or exact wording. For a one-sentence edit, apply the
guide without loading every example. Supporting files are not assumed to be loaded
just because this skill is available.

## Draft

1. Identify the audience, purpose, requested length and decision or action needed.
   Use the context already supplied. Ask only when missing information would change
   the substance; do not make a simple drafting request into an interview.
2. Lead with the point. Keep useful background, then explain the issue, recommendation
   and benefit in the order that suits the task.
3. Use short paragraphs and specific language. Keep technical terms when they help
   the intended audience. Be constructive without diluting the concern.
4. Match the structure to the task. A chat message usually needs a few paragraphs,
   not an executive summary, a table and a conclusion. A proposal may need headings,
   tradeoffs, a small example and adoption steps.
5. For a LinkedIn post, open with a punchy observation tied to the work, explain it
   and your contribution, then give readers a useful takeaway or a natural invitation
   to respond. Credit collaborators, keep internal details private, and use verified
   outcomes. Read the LinkedIn example before a substantial professional post.
6. Separate existing behavior, observations, assumptions and proposed changes. Do
   not turn a preference into an agreed policy or a suggestion into implemented work.
7. Preserve disagreements and limitations. Do not invent evidence, measured benefits,
   test results, citations, consensus, ownership, deadlines or commitments by the user.
8. Stay within the request. Drafting does not authorize implementation, publishing,
   sending messages, changing agent configuration or saving new personal memories.

## Review before returning

- Would the user naturally send this to the stated audience?
- Is the recommendation clear without reading the whole document?
- Is every claim supported or appropriately qualified?
- Can an introduction, repeated point or closing summary be removed?
- Do headings, bullets, tables, bold text and code earn their space?
- Is the level of formality appropriate, with no sales language or forced enthusiasm?
- Did the wording preserve the user's position without making it more confrontational?
- Is it clear what the recipient is being asked to consider or do, when relevant?

Return the requested draft directly unless a short caveat is needed to prevent a
misleading claim. Do not explain that the writing has been made "human" or claim it
will evade AI detection. Natural writing comes from clear reasoning and restrained
editing, not invented personal anecdotes or deliberate mistakes.

## Using this as a default

Skill discovery is not the same as always-on instructions. For a consistent personal
default, install this skill **and** merge [the global instruction snippet](global-instructions.md)
into the host's supported persistent instructions. Follow the [setup guide](README.md).
Installing this package does not edit those instructions automatically.

When delegating a draft, pass the audience, purpose and these writing expectations
to the drafting agent; have it load this skill if available. Do not assume separate
sessions, subagents or other products inherit the same files or context.

Specific instructions for the current document and applicable project or organization
requirements take priority over stylistic defaults. Use specialized skills for the
medium, such as slide design, without making every output follow one template.
